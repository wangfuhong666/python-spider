# 中国工控网爬虫：示范代码说明

## 一、示范代码与原代码的区别

两份代码生成的文件都是 `中国工控网.csv`，列名和字段顺序也完全相同：公司名称、详情页url、邮箱、网址、电话、地址、邮编/联系人、传真。这样可以直接把两份 CSV 放在一起比较。

| 方面 | 原代码 | 示范代码 |
| --- | --- | --- |
| 字段获取方式 | 用正则表达式从整页 HTML 中查找内容 | 用 XPath 定位“联系方式”区域，再读取每个 `p` 标签的“标签：值” |
| 两种详情页 | 用 `if 'y_Contact' in res.text` 分支，并分别写多条正则 | 同样识别两种页面，但通过 `labeled_fields()` 统一读取标签和值 |
| 空白处理 | `get_con()` 只处理经过正则得到的字段；公司名称直接写入 CSV，没有清洗 | 所有写出的网页文字都经过 `clean_text()`，包括公司名称 |
| 连续空白 | 之前会保留字段中间的多个空格、全角空格或网页排版空白 | 连续空白统一压缩为一个普通空格，并移除首尾空白 |
| 链接拼接 | 人工写 `'https:' + href` | 用 `urljoin()`，可正确处理相对链接、绝对链接和不同形式的 URL |
| 网络请求 | 每次独立请求，没有超时设置 | 使用 `requests.Session()` 复用连接；设置 15 秒超时、HTTP 状态检查和 0.2 秒请求间隔 |
| CSV 编码 | `utf-8` | `utf-8-sig`；内容仍是 UTF-8 CSV，但带 BOM，Excel 更容易正确识别中文 |

示范版没有改变原有数据含义。例如地址、很长的网址、说明性电话仍会保留，因为它们是真实数据；代码只清理没有业务含义的排版空白。

## 二、为什么这样写

### 1. 先把文本清洗规则放在统一入口

`clean_text()` 做三件事：把 HTML 空白实体换成普通空格、把连续空白压缩为一个空格、移除首尾空白。网页往往会为视觉排版插入普通空格、全角空格、不换行空格、制表符或换行；这些字符出现在 CSV 中后，自动调整列宽会把它们当作真实宽度。

原代码中的 `get_con()` 已经开始承担这项工作，但列表页的公司名称通过 `li.xpath('./a/text()')[0]` 直接写出，绕过了 `get_con()`。示范版让公司名称也经过 `node_text()`，所以规则对每一列一致。

### 2. HTML 页面优先用 XPath，不优先用正则

正则在“文本有固定前后标记”的场景很方便，但 HTML 标签、属性、换行和网页小改版都会影响它。此网站的联系方式已经有明确的容器和 `p` 标签，因此更适合先定位容器，再按“标签：值”读取。

例如页面中的“电话：021-xxx”无论电话值是在纯文本还是 `a` 标签里，`node_text()` 都能取到文字；而用整页正则时需要依赖精确的标签写法。

### 3. 空白不能一律删除

对于地址、公司名、电话说明等文本，多个排版空格应压缩成一个，但不能全部删除：两个电话号码之间、英文单词之间的一个空格可能有意义。邮箱和网址原则上不应有内部空格；如果以后发现这两列被网页插入空格，应对这两个字段单独使用“删除全部空白”的规则，而不要影响地址和电话。

## 三、以后怎样修正和提高

1. 在写入 CSV 之前清洗，而不是依靠 Excel/WPS 手工修数据。表格软件的自动列宽是正常功能，它只是暴露了原始数据中的异常字符或真实长文本。
2. 抓到值后先用 `print(repr(value))` 抽查。普通 `print()` 看不清多个空格；`repr()` 会显示 `\n`、`\t` 等隐藏字符。
3. 所有来源的文字都使用同一个清洗函数。不要只清洗某一个分支或某几列，否则同类脏数据会从遗漏的路径进入 CSV。
4. 把“提取”和“清洗”分开：XPath/正则负责找到值，清洗函数负责规范文本，CSV 代码只负责保存。这会让排错更容易。
5. 对每种页面结构准备最小样本。网站改版或新增字段时，先用少量链接验证字段，再全量运行。
6. 为请求加超时、状态检查和适度间隔。超时可避免程序长时间卡住；状态检查能发现 404/500；间隔可降低对站点的压力。
7. 不要把“长数据”和“脏数据”混为一谈。很长的 URL、完整中英文地址、整句联系电话说明都可能是真实值。对它们应在表格中设置最大列宽和自动换行，而不是删除信息。

## 四、整体爬虫思路

```text
请求首页
  -> 提取公司名称与详情页链接
  -> 逐个请求详情页
  -> 判断详情页属于哪一种联系方式结构
  -> 按字段标签提取邮箱、网址、电话、地址、邮编/联系人、传真
  -> 统一清洗文本空白
  -> 组合为固定 8 列的一行数据
  -> 写入 UTF-8 CSV
```

这类爬虫可以分成四层理解：

1. **请求层**：`requests` 下载网页；
2. **解析层**：`lxml.etree` 把 HTML 变成可用 XPath 查询的树；
3. **数据层**：从列表页和详情页取字段，并把两种页面结构统一成同一组列；
4. **输出层**：使用 `csv.writer` 写入固定表头与固定列数。

只要每层各自负责一件事，网站页面的小变化、数据中的异常空白和导出格式问题都会更容易定位。
